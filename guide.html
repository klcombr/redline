§ 1

The standard

The core principle. Everything below follows from this.

Design from the product, the task, the content, the brand, the environment, the interaction — not from a collection of fashionable UI patterns.

1 Specific > trendy Design from the product, the task, the content — not from a collection of fashionable patterns.
2 Purpose > decoration Every significant visual decision must have a reason. No job, no place.
3 Clarity > complexity What should the user notice first, second, third? Design around that order.
4 Identity > template Still correct with another company’s logo and copy? Then it is too generic.
5 Hierarchy > ornament Primary attention, secondary information, supporting detail. If everything is emphasized, nothing is.
§ 2

Know the product

Fact discipline. Missing content is a constraint, not a licence to decorate.

Before designing, determine the minimum necessary product truth. Answer these seven questions:

1What is the product?
2Who is using it?
3What is the primary user goal?
4What action matters most?
5What information needs the most attention?
6What makes this product different?
7What constraints exist?

Do not invent

statistics · customers · testimonials · reviews · partnerships · features · capabilities · claims · product metrics

If information is missing, design around what is actually known. Do not compensate for missing content by adding decorative UI.

§ 3

Three dials

Dial values follow the product. Never raise them just to look impressive.

Not every interface is spacious. Not every dashboard is dense. The dials are set by the task, and REDLINE enforces the setting.

Variance

conventional · stable · predictable asymmetric · editorial · unusual composition

Composition, not decoration

Motion

feedback only · small transitions immersive interaction · scroll choreography

Movement must communicate

Density

presentation · marketing · storytelling dashboards · tools · professional interfaces

Follow the task, not the fashion

§ 4

The removal catalogue

Strikethrough = delete. Hover an item to reconsider it.

Patterns to avoid unless the product genuinely requires them. The burden of proof sits with the pattern — and 26 of them have the burden.

A · Layout

  • Generic hero + CTA + mockup
  • Identical centered landing pages
  • Excessive cards
  • Card-inside-card layouts
  • Uniform card grids
  • Oversized dashboard mockups
  • Repetitive section layouts
  • Components added only to fill whitespace

B · Decoration

  • Random gradients
  • Decorative glassmorphism
  • Excessive blur
  • Excessive shadows
  • Excessive glow
  • Excessive animation
  • Floating blobs
  • Arbitrary abstract shapes
  • Fake “3D” objects

C · Detail

  • Unnecessary rounded rectangles
  • Excessive pills
  • Badge spam
  • Icon spam
  • Stock-looking illustrations
  • AI-generated decorative imagery without art direction

D · Copy & claims

  • Generic SaaS copy
  • Meaningless statistics
  • Giant headings with no structural purpose

Remove before adding.

If removing it changes nothing about understanding or interaction, remove it.

§ 5

The two gates

Both run before shipping. No exceptions.

Gate 01 · Removal

If I remove this, does the product become harder to understand, use, navigate, or recognize?

If no — remove it. For every unusual element, the same question: what specific product reason justifies this? No good answer, do not add it.

Gate 02 · Template

Replace the logo and copy with another company’s. Does it still feel correct?

If yes, the design is too generic. Do not fix with decoration — change composition, typography, hierarchy, interaction, content structure, visual language.

§ 6

Motion & 3D, with the packs

GSAP for motion, Three.js for 3D. The brief decides which.

The dials are set by the task — and the brief sets the dials. Asked for animated, REDLINE ships the eight official GSAP skills and the page-transition pattern so the implementation is correct: scrubbed, registered once, cleaned up on unmount, respectful of prefers-reduced-motion. Asked for 3D, it ships the ten official Three.js skills for real scenes. This very page redlines the statement above with one scroll-scrubbed ScrollTrigger — and every link between pages sweeps through the transition overlay.

gsap-core Core API — gsap.to/from/fromTo, eases, staggers, defaults. Any GSAP work starts here; matchMedia for reduced-motion.
gsap-timeline Choreographed sequences — position parameter, nesting, playback. Loads when order matters.
gsap-scrolltrigger Scroll-linked animation, pinning, scrub, triggers. Loads when the page answers to the scroll.
gsap-react useGSAP hook, context, cleanup on unmount, refs. Loads on React / Next.js.
gsap-frameworks Vue, Svelte & co — lifecycle, scoping, onDestroy cleanup. Loads outside React.
gsap-plugins Flip, SplitText, MorphSVG, MotionPath, Draggable, CustomEase… Loads when a tween needs a plugin — register once.
gsap-performance Transforms only, no layout thrash, mindful will-change, 60fps. Loads when it must not jank.
gsap-utils clamp, mapRange, normalize, interpolate, snap, wrap, pipe. Loads when values need mapping, not magic numbers.

THREE.JS · 3D — ONLY WHEN THE BRIEF ASKS

threejs-fundamentals Scene, camera, renderer, Object3D hierarchy, coordinate systems. Every 3D scene starts here.
threejs-geometry Built-in shapes, BufferGeometry, custom geometry, instancing. Loads when the scene needs shape.
threejs-materials PBR, phong, basic, shader materials — properties and tuning. Loads when surfaces need a look.
threejs-textures Texture types, UV mapping, environment maps, colour spaces. Loads when the surface needs detail.
threejs-lighting Light types, shadows, environment light, lighting performance. Loads when the scene needs depth.
threejs-shaders GLSL, ShaderMaterial, uniforms, custom visual effects. Loads when stock materials are not enough.
threejs-loaders GLTF, textures, HDR, async patterns, loading progress. Loads when there are assets to load.
threejs-animation Keyframes, skeletal animation, morph targets, mixing. Loads when the scene moves.
threejs-interaction Raycasting, controls, mouse/touch input, object selection. Loads when the scene answers to the user.
threejs-postprocessing EffectComposer, bloom, DOF, screen-space grading. Loads when the frame needs a finish.

§ 7

The method

Shape before code. The page is one composition.

01UnderstandProduct, user, task, content, constraints.
02ShapeHierarchy, composition, navigation, interaction, responsive behaviour — before decorative details.
03EstablishTypography, colour, geometry, spacing, density, variance, motion.
04BuildSemantic structure and reusable primitives.
05RefineHierarchy, spacing, typography, alignment, states, motion, responsive behaviour.
06AuditUsability, accessibility, responsive behaviour, performance, consistency, content accuracy, visual hierarchy.
07DistillRemove anything that does not contribute. Do not add more because the page feels empty.
§ 8

The final rules

Adjectives are not goals. They arrive on their own — or not at all.

Optimize for

  • Clarity
  • Hierarchy
  • Usability
  • Identity
  • Consistency
  • Intentionality
  • Product truth

Never optimize for

  • Modern
  • Beautiful
  • Premium
  • Futuristic
  • Trendy
  • Clean

Specific > generic.  Purpose > decoration.  Hierarchy > spectacle.  Product identity > template.  Simple implementation > unnecessary complexity.  Remove before adding.
